## Recent work

### Treg

[Treg](https://treg.to) is OpenRouter for agent tools. One token lets an agent call 4,000+ API endpoints across 113 providers. The credential stays on the server, and the agent asks for the job rather than a vendor. I run hackathon sponsorships, demos, and developer content. The docs entry is [treg.to/llms.txt](https://treg.to/llms.txt). Treg on X: [@treg_ai](https://x.com/treg_ai).

The public reference build is [Treg Lens](https://github.com/tomcharlesosman/treg-lens), live at [treg-lens.vercel.app](https://treg-lens.vercel.app). It is an open-source, MIT-licensed AI visibility workspace. You bring your own Treg key, review a brand profile and buyer questions, then track answers and citations from ChatGPT, Gemini, Google AI Mode, and Perplexity.

### Juno

[Juno](https://x.com/JunoAgent) is the AI operator behind ZHC Institute, built to help founders design and run companies operated by agents. On the Institute, Builder is the path that turns an idea into a venture with Juno and follows its agents from a dedicated workspace.

### ZHC Institute

[ZHC Institute](https://www.zhcinstitute.com) is the platform and practitioner network for people building Zero-Human Companies. Founders set direction and agents carry out the work. The public product has two paths: Swarms, where agents investigate a focused idea in parallel and publish a shared brief, and Builder, which launches a venture with Juno. Around that sit research, operational playbooks, weekly live build sessions, and the member network.

### Critical Supply

[Critical Supply](https://findcriticalsupply.com) is Middleman Technologies’ AI-driven supplier discovery product for United States and United Kingdom data centres, grid connections, and critical power. The public directory is source-backed and grouped by procurement category and project stage. Listings are a starting point: each record shows what was checked, and the buyer verifies the supplier before procurement.

## How I work

1. Start with a real task and get the whole path working.
2. Test the failure paths, not only the demo path.
3. Turn the build into the smallest useful example another developer can run.
4. Teach the decisions, tradeoffs, and debugging process in plain language.
5. Feed developer friction back into the product.
